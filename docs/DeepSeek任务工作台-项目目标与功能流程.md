# DeepSeek 任务工作台开发 Spec

版本：v0.6｜2026-09-24
适用：Chrome Manifest V3 扩展，运行在 DeepSeek Web（DSW）

2026-10-12 增补：先实现少量本地记忆快照、删除意图与自动局部恢复，规则见 4.4；其他记忆重构提案暂不纳入实施范围。

2026-10-12 发送与限流修复：普通会话仅在首条消息带入生效个人记忆，不依赖项目记忆开关；该开关控制首条消息是否同时带入所选项目的目标和记忆。两类记忆均按“范围 → 类别 → 条目”分组，类别顺序与管理页一致，用两句话说明附带内容和背景用途，并明确回答独立的本轮问题。后续轮次、刷新和重新打开后不重复，中途开启也不补发。个人记忆单独发送不会强制归入项目。接续到新会话时，个人与项目记忆随新会话首条消息重新带入。插件历史读取按账号间隔至少 1 秒、同会话并发读取合并；限流后冷却 60 秒并停止本次扫描，保留本地会话，不自动重发消息。查看历史自动化会话不触发全量扫描，自动化运行时取消重复历史轮询。下文项目记忆开关关闭时的“原生发送”指保留原生发送操作，首条消息仍可附带个人记忆。

## 1. 开发依据

本文件是开发时的需求依据；[本地存储数据表设计.md](本地存储数据表设计.md) 定义最小本地数据；[api-recon-schema.md](api-recon-schema.md) 仅作 DSW 抓包字段参考；[我的需求.md](我的需求.md) 保留原始想法。已有插件代码可以复用，若旧实现、旧界面与本 Spec 冲突，以本 Spec 为准。网页行为与抓包字段发生变化时，以 Chrome 实测调整适配层。

先实现能使用的版本，再按实际问题补强。不设代码行数限制，不要求为每个边界情况建立完整框架。用户会手动测试；开发时可运行 Chrome 做基础功能冒烟验证。

### 未写明部分由 Codex 设计

本 Spec 规定目标和关键边界，不是穷尽的功能清单。开发时若发现完成主流程还需要额外的交互、状态、设置或异常处理，Codex 应结合现有代码和 Chrome 实测自行设计并实现，优先采用简单、易理解、能稳定工作的方案。可以调整模块划分、增加必要的数据字段或辅助功能；不要因文档未逐项写明就留下明显断点，也不要为了未来可能用到的功能提前建复杂框架。

重要取舍简要记入开发文档：解决了什么实际问题、用户会看到什么、还未覆盖什么。只有当选择会改变上述核心体验、涉及删除用户或 DSW 数据，或确实无法从现有信息判断用户意图时，再向用户确认；一般实现细节由 Codex 决定并继续推进。

## 2. 必须实现的体验

1. **保留 DSW 原生能力。** 用户仍可新建会话、提问、看回答，并使用原生会话搜索、重命名、置顶、编辑、重新生成和删除。插件不要替换 DSW 的回答区。
2. **项目树。** 插件提供两层目录：第一层项目，第二层该项目的会话；另有“未归类”。每个项目及“未归类”内部的会话按最新消息时间从新到旧排列：已读取消息时使用末条消息时间，其余先使用 DSW 会话列表的更新时间；时间尚未获取时暂按原生侧栏顺序，获取后自动重排。用户可新建、改名、归档项目，手动移动会话。项目和会话名称都可改；会话改名需同步到 DSW，项目名只存本地。
3. **新会话自动归类。** 新用户会话完成首轮回答、标题更新后，插件另建一个 DSW 会话，请 DeepSeek 用固定 JSON 选择已有项目、新项目建议或未归类。已有项目匹配明确时本地归类；建议新项目时让用户确认后创建并移动原会话。归类会话是真实 DSW 会话，原生历史可见，不能递归归类。
4. **项目记忆开关。** 在 DSW 输入框的“深度思考”“智能搜索”按钮右侧放置“项目记忆”按钮，沿用原生按钮的外观及悬停、按下、开启状态交互。关闭时保留原生发送，插件仍可采集和归类；已归属项目的完整问答仍累计到项目记忆。所有普通会话（含未归项目）的完整问答计入个人记忆，自动化会话除外。个人记忆只随首条消息发送；首条消息发送时若已开启项目记忆且已选项目，同时带入项目目标和记忆，后续不重复。项目及个人记忆分别达到设置的轮数后自动新建 DSW 自动化会话整理，也可在管理页手动触发。未归类时先让用户选项目。
5. **记忆管理。** 插件设置页有“管理记忆”入口，打开独立网页。左侧第一行是个人记忆，之后每行一个项目并显示记忆条数；右侧可查看、新增、编辑、停用记忆，并导入、导出个人或项目记忆。个人记忆跨会话/项目，项目事实只属于对应项目。管理页显示当前数据账号，旧版同一扩展存储中的项目与记忆会在首次读取时迁入。
6. **长会话接续。** 设置页用下拉框调整最大上下文预算、接续提醒比例和回答预留量，默认均选“适中”；记忆按旧会话顺序更新，个人与项目使用独立提示词，支持主动更新。项目记忆开启且会话接近阈值时，插件新建同项目后继会话，带入有效目标、约束、进展、下一步和本轮问题。没有 DSW token 数据时，可用正文长度作保守接续判断，但不显示伪造的 token 数。原会话保留。发送结果不明时保留草稿，不自动重复发送。
7. **消息信息。** 项目会话中尽量在每条用户消息和助手回复正文下方显示 DSW 日期和抓包返回的累计 token。首条消息以 0 为起点，其余相邻消息都有累计值时，以差值显示“本次 xxx tokens · 累计 xxx tokens”；缺少前一条累计值时只显示累计值，缺少当前累计值时不显示 token。本次观测到的等待时间只在后台记录，不在对话页面显示。

首版启动时把 DSW 页面已加载到原生侧栏的历史会话登记到“未归类”，后续侧栏加载出的历史会话也同样登记；不批量拉取全部旧历史消息，也不对旧会话自动归类。自动归类只处理插件启用后新建、完成首轮回答的会话。不做附件跨会话恢复。插件创建的归类/整理会话会留在 DSW 原生历史，并集中显示在固定的“自动化会话”收纳项目中；该项目不参与归类、记忆或项目目标操作。

## 3. 界面要求

项目树与 DSW 页面风格协调，不遮挡原生输入框、回答区或原生会话操作。树节点、选中状态、展开收起、未归类提示、项目记忆按钮的开启状态应一眼可辨。记忆页使用左侧目录、右侧内容的稳定布局，编辑与导入导出入口容易找到。可以重做现有插件的前端，不必沿用效果不佳的旧界面。

~~~text
项目
├─ 项目 A
│  ├─ 会话 1
│  └─ 会话 2
├─ 项目 B
│  └─ 会话 3
└─ 未归类
   └─ 新会话
~~~

## 4. 核心流程

### 4.1 新会话归类

~~~mermaid
flowchart LR
    A[DSW 新会话提问] --> B[回答完成/标题更新]
    B --> C[采集会话 ID 与本轮内容]
    C --> D[新建 DSW 归类会话]
    D --> E[解析固定 JSON]
    E --> F{结果}
    F -->|已有项目| G[本地关联]
    F -->|建议新项目| H[用户确认后创建并移入]
    F -->|无效或不确定| I[未归类]
~~~

归类输入只需本轮问题、必要的回答内容，以及已有项目的 ID、名称和简短目标；不要把全部项目记忆发给归类会话。JSON 至少包含原会话 ID、选择类型、已有项目 ID 或建议项目名。插件校验 ID 后再保存；用户手动移动过的会话不被旧归类结果覆盖。

### 4.2 项目记忆与发送

~~~mermaid
flowchart LR
    A[点击发送] --> B{会话首条消息?}
    B -->|是| C[个人记忆及已开启的项目记忆分组]
    B -->|否| D[保留原始问题]
    C --> E[包装背景与本轮问题]
    E --> F[项目记忆开启时检查接续预算]
    D --> F
    F --> G{需要接续?}
    G -->|否| H[当前会话发送]
    G -->|是| I[新会话首条带入两类记忆与近期进展]
    H --> J[采集完整回答/更新记忆]
    I --> J
~~~

首条消息的记忆按管理页的“范围 → 类别 → 条目”组织。个人类别为“资料、偏好、工作方式、术语、其他”，项目类别为“目标、约束、决定、进展、阻塞、下一步、其他”；每类只显示一个类别标签，下方条目从 1 开始编号，不给每条重复加标签。多行条目保留缩进，未知旧类别归入“其他”，预算不足时保留完整条目。用一两句话说明附带范围和背景用途，再单独列出本轮问题。用户手动修改优先；自动整理不要覆盖人工固定内容。原始输入和插件补入的记忆要分开保存，避免把补入资料当成用户的新要求。后续消息直接发送原始问题，但仍检查接续预算；接续新会话的首条消息重新带入两类记忆和近期进展。接续成功以 DSW 新会话出现对应用户消息为准；无法确认就保留草稿供核对。

### 4.3 原生变更同步

DSW 标题更新后刷新本地会话标题；项目改名不改 DSW 标题。DSW 编辑/重新生成会形成分支，展示和记忆整理只取当前分支；若来源变了，相关自动记忆待重新整理。DSW 删除会话不应自动删除整个项目。用户手动移出或改归属后，停止把该会话内容用于旧项目记忆。

历史消息的编辑框也按个人/项目显示开关过滤记忆，切换时保留已修改的问题。提交编辑只还原该消息原来附带且被隐藏的记忆，保留可见记忆的人工修改，不重新附带当前最新记忆；只改写会话、可见草稿和消息 ID（可获取时）匹配的原生编辑请求。普通新消息不受编辑上下文影响，关闭编辑时清除临时上下文。

### 4.4 记忆保护与局部恢复

每个账号最多保留最近 5 份记忆快照，记忆变更与快照原子写入。批量删除或清空类别条目时，同时记录删除意图并清除各快照中的对应内容；正常增量整理过滤再次返回的相同内容，不撤销已处理消息。删除意图按 ID 或同范围的规范化内容摘要匹配，不做语义匹配；用户主动补充或导入可以重新保留。

读取记忆、修改记忆前、队列出队前及每分钟检查时，自动补回缺失、字段损坏或版本回退的条目，保留有效的新版本。生效的自动记忆须核对来源消息、分支、起始时间及项目归属；无法核对则暂不恢复，已停用或人工固定的条目保留原状态。恢复不请求模型、不重复发送历史会话、不改变消息处理记录；暂停自动化队列时本地检查仍运行。设置与记忆页面标题旁的详情符号显示快照数量和恢复情况。

保护从启用此功能时建立基线，不补采更早历史。整个扩展本地数据被删除时，内部快照同样丢失，需要用事先导出的文件恢复。无需为这两项能力引入独立事实库、向量服务或模型修复任务。

## 5. 最小插件架构

~~~mermaid
flowchart LR
    P[DSW 页面] <--> C[内容脚本：项目树/按钮/采集]
    C <--> B[后台：归类/记忆/接续协调]
    B <--> DB[(IndexedDB)]
    B <--> M[设置页与记忆管理页]
    B --> A[DSW 适配器：新会话/发送/标题]
    A --> P
~~~

- **内容脚本**只处理 DSW 页面观察和界面交互；DSW 选择器、抓包解析集中在适配器里。
- **后台**协调归类、记忆和接续。自动发送先记录草稿和目标会话，恢复后先核对，避免重复发送。
- **IndexedDB**保存账号隔离的项目、会话映射、必要消息、记忆、设置和进行中的作业。具体字段见本地数据表文档。
- **记忆管理页**读写本地记忆，导入导出 JSON；不直接修改 DSW 服务器会话。

## 6. 开发顺序与基础验证

先接入新会话采集和项目树，再实现独立 DSW 会话归类与手动纠正；随后做记忆管理页和项目记忆按钮，最后做预算提示及后继会话。可复用已有代码，但前端按本 Spec 调整。

开发者在 Chrome 中做少量冒烟检查即可：新会话能出现在树里并归类；用户能改项目与会话归属；首条消息能带入分组个人记忆，记忆按钮开启时同时带入项目记忆，后续和刷新后不重复；记忆页能编辑和导入导出；达到阈值时能建立后继会话。遇到网页能力不稳定，先保证 DSW 原生对话可继续使用并显示失败状态。更细的使用测试由用户手动完成。
