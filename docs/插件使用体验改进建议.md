# DeepSeek 项目工作台：小改动优先的体验建议

日期：2026-10-11。依据当前仓库的 0.9.0 实现，从实际使用流程评估；以下工作量是相对估计。

最值得继续改善的是：让用户知道记忆何时生效、自动化为什么启动，以及出错后下一步怎么处理。先把现有能力做得可见、可控，不急着增加新的复杂功能。

后续 UI 精简已实现：解释文字收进悬停/聚焦可见的 `i` 提示；设置标签和控件统一对齐，普通操作与保存按钮分级。记忆条目不再提供逐条编辑、停用、固定按钮，只在类别标题提供编辑入口；类别内各条内容独立，整类原子保存。导入、导出和批量删除收进“更多”，选择框仅在批量模式显示。窄屏使用一个自然滚动页面，成功提示短暂显示后收起。因此，下文的窄屏布局建议已完成，固定属性文案可放在类别编辑详情中，无需恢复逐条固定按钮。

## 本次已实现

| 内容 | 用户能感受到的变化 |
| --- | --- |
| 预算字段兼容 | 旧后台或缺字段快照不再让整个记忆面板崩溃，改为显示预算暂不可用 |
| 个人记忆分组 | 固定顺序为资料、偏好、工作方式、术语、其他；项目保留目标、约束、决定、进展、阻塞、下一步、其他 |
| 组内稳定排序 | 固定记忆优先，其次生效记忆，再按内容排序；刷新时不会仅因更新时间变化而频繁换位 |
| 自动化队列 | 设置页显示归类、两种记忆整理、接续任务；可暂停/继续、调整等待顺序、取消等待任务、查看运行会话和最近结果 |
| 统一增量整理 | 同一项目一次请求更新个人与项目记忆；只提交已有记忆与新增消息，独立记录处理结果，删除记忆不重发旧消息 |
| 记忆变更与重试 | 项目记忆支持更新和停用，手动固定项受保护；失败整批回滚，可在设置重试，保存失败可复用有效模型结果 |
| 批次信息 | 队列显示会话数、轮数、更新范围、首次/重试和复用结果状态；同账号记忆顺序执行，避免基于旧记忆互相覆盖 |
| 记忆起始时间 | 默认记录插件首次运行时间；用户可选择本机时区的时间点，筛选该时间及之后创建的普通会话 |
| 批量删除 | 个人和项目记忆均可勾选、全选当前范围、批量删除；切换范围清空选择，删除前显示条数及固定条数 |
| 防止旧结果写回 | 删除会提升该范围的记忆版本，删除前启动的整理结果会被拒绝；旧编辑窗口不能重建已删除条目 |

起始时间的边界：按会话创建时间筛选，旧会话后来继续聊天仍不纳入；优先依据首条用户消息的时间，无法确定创建时间时暂不整理。修改时间保留已有记忆，并通知已打开的 DeepSeek 页面补扫。此前未记录首次运行时间的旧安装，从升级到本次实现后的首次运行开始记录。

队列的边界：暂停阻止新任务启动，已经运行的任务继续；运行任务可查看，取消入口只提供给等待任务。取消记忆整理会跳过该批轮次，启动补扫不会立即把它重新排入；后续的新轮次仍可触发整理。取消接续保留原始草稿。批量删除会真正移除本地记忆记录；用户今后再次明确表达同一事实时，仍可能被重新学习。

## 优先做的低成本改进

| 优先级 | 使用中的不顺手 | 建议的小改动 | 完成标准 | 工作量 |
| --- | --- | --- | --- | --- |
| P0 | 开关名字容易让人误以为关闭了记忆 | 在“显示自动添加的记忆”旁明确写“仅控制显示”；项目记忆按钮写清“本次发送会带入”或“本次发送不带入” | 用户无需翻文档就能分清记忆更新、发送注入、聊天显示三件事 | 小 |
| P0 | 整理完成但没有新增时，很像插件没工作 | 在个人/项目范围内显示最近整理时间、处理轮数、写入/停用条数；空结果显示“已检查，没有适合长期保存的信息” | 看面板就能分清未开始、排队、失败、正常空结果 | 小 |
| P0 | 错误文案同时出现 bytes、tokens 等口径 | 提示、预算条、失败原因统一写“按 UTF-8 字节保守计”；精确 token 数据才用 tokens | 用户能解释为什么几百个中文字符就接近个人记忆上限 | 小 |
| P0 | 自动归类结果建议新项目，但设置页只有提示与忽略 | 待核对任务直接提供“创建此项目并归入”和“保持未归类”；复用现有确认接口 | 看到待核对任务时能在同一处做完处理 | 小 |
| P1 | 条目多时只能滚动找，停用条目挤占注意力 | 增加一个关键词搜索框和“全部 / 生效 / 停用或失效”筛选；显示筛选后的条数 | 可按内容找到记忆，筛选后全选明确只选可见条目 | 小 |
| P1 | 个人记忆保留来源会话，却缺少便捷的来源入口 | 自动条目附“来自某会话 · 日期”和“打开来源”；手工条目标“手工添加” | 怀疑内容时一键回到来源核对 | 小 |
| P1 | “固定”含义不明确，用户不敢点 | 改为“固定，防止自动改写”，并给简短说明；继续允许用户主动编辑与删除 | 用户知道固定影响自动整理，不影响人工操作 | 小 |
| P1 | 取消、失败、完成混在一长串历史里难扫描 | 队列历史补一行人话结果，如“写入 2 条”“没有新增”“来源已变，请重新整理”；失败优先展示可执行按钮 | 不读原始 JSON 也能理解结果与下一步 | 小 |
| P1 | 起始时间之后仍有会话缺少时间，被静默排除 | 范围提示显示“符合时间范围 N 个，创建时间待确认 M 个”，提供“重新检查会话”按钮 | 用户知道为何有些会话没有参与整理 | 小 |
| P2 | 切换账号后担心在错误账号里操作 | 在设置页顶部把当前账号做成醒目的固定提示；切换时清空勾选和编辑状态，并提示一次 | 批量删除、导入、保存前清楚知道目标账号 | 小 |

## 需要稍多一点改动，但回报明显

1. **给自动归类一个独立开关。** 当前新会话首轮完成就会发起归类，暂停队列只能把归类也一起积压。增加“新会话自动归类”开关并在关闭时不创建归类任务，可以让只想用记忆的人保留简洁的项目树。开关说明应交代会新建辅助会话。

2. **按会话排除记忆整理。** 在会话菜单加“不从此会话整理记忆”，同时影响个人和项目两个入口。临时问答、代别人提问和敏感讨论无需依赖起始时间来整体排除。被排除的会话仍能正常聊天，并有一个简短标记。

3. **批量删除后的短时撤销。** 删除前确认已能减少误操作；进一步可保留一个短期撤销批次，明确过期后清理，避免永久保存已删除文本。撤销应恢复原条目，仍保留删除前整理结果的失效标记。

4. **个人记忆冲突只对冲突项确认。** 人工固定条目与用户最新表达冲突时，给出“保留原条目 / 采用新表达”的一次性选择。无需把所有自动整理都变成审批流程。

## 当前设计里最该澄清的地方

- **弹窗承担了完整设置和记忆管理。** 当前工具栏 action 直接打开完整 options 页面；多栏、大列表和对话框放在小弹窗里会拥挤。可以把工具栏入口改成打开完整设置标签页，或只留简短状态和“打开管理页”按钮，不必重新设计整套页面。
- **窄屏时上下各占半屏。** 当前响应式布局把设置和记忆管理分成两个独立滚动区域，长列表更难浏览。小屏改成一个自然滚动页面即可；宽屏保留现有分栏。
- **按旧会话更新。** 已移除轮数阈值；界面说明会话顺序、旧会话变化后的重放与主动更新入口。
- **自动化会话会留在远端历史。** 关闭辅助标签页并不会删除 DeepSeek 会话。首次产生辅助会话时说明一次，并沿用“自动化会话”收纳入口，让用户能自行核对；不需要新增定时清理功能。
- **个人记忆预算很小，需要明确处理优先级。** 已固定的记忆优先保留，超额条目保留但停用的规则应可见；提示用户先精简或停用，并展示最占容量的条目，避免只报“容量不足”。
- **README 的新旧架构说明混杂。** 顶部描述 IndexedDB/0.9.0，后面仍描述旧存储、旧开关和旧归类格式。把旧版细节移到单独的历史说明，当前文档只讲现有界面，能明显减少“怎么找不到这个按钮”的困惑。

建议下一轮先做：状态/单位文案统一 → 新项目归类确认按钮 → 搜索与状态筛选 → 来源链接。这些改动复用已有字段和接口，对日常使用的帮助最直接。
