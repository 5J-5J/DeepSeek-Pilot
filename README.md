# DeepSeek 项目工作台

插件把 DeepSeek 左侧已加载的会话显示为「项目 → 会话」树。每个项目和“未归类”内的会话按最新消息时间从新到旧排列；尚未读取消息的会话暂用 DeepSeek 会话列表时间。插件首次运行时，页面已加载的历史会话会进入“未归类”；后续原生侧栏加载出的旧会话也会出现。旧会话不会自动 AI 归类，但可以手动移入项目。DeepSeek 原会话节点仍保留在 DOM 中，用于复用原生导航和菜单。

> 当前扩展入口是 `core/manifest.json`（0.9.0）。下方部分 0.8.x 功能说明尚未按新架构更新；当前数据层以 IndexedDB 和 `docs/本地存储数据表设计.md` 为准。

0.9.0 中，已归入用户项目的完整问答都会累计到项目记忆；所有普通会话（含未归项目）累计到个人记忆，自动化会话除外。「项目记忆」按钮只控制发送时是否带入记忆。达到设置页的轮数阈值时，插件会自动新建 DeepSeek 自动化会话整理（默认 5 轮，可设 1–30）。插件启动时会读取已登记的普通会话历史，补记当前分支中尚未整理的轮次；达到阈值便自动更新，已完成的整理不会重复计数。记忆管理页显示个人及各项目的待整理轮数，项目记忆也可随时手动整理。插件发送的用户原文单独保存；自动整理优先读取原文，不把补入的项目记忆当成新要求。若发送结果无法确认，设置页的待核对作业会显示并允许复制原始草稿；重新发送前应先核对 DeepSeek 历史。设置页和记忆管理页使用当前 DeepSeek 账号的本地数据。

设置页的上下文预算与记忆更新轮数使用预设下拉框，默认选“适中”。记忆管理页显示数据账号、项目和各项目的记忆条数。首次读取时会把同一扩展安装中 `chrome.storage.local` 保存的旧版项目和记忆迁入新数据表，不覆盖已经存在的新项目或记忆；旧数据会保留。不同扩展安装 ID 的存储彼此隔离，无法直接自动迁入。

## 当前功能

- 左侧栏以项目分组真实 DeepSeek 会话，项目可展开或收起；
- 未归属的会话显示在「未分类会话」，不再暗中绑定“最近项目”；
- 每个插件会话行的 `•••` 会打开 DeepSeek 原生菜单，并追加「移动到项目…」「移出项目」「项目详情」；
- 新建、重命名和删除项目；点项目名打开右侧详情，点小箭头折叠会话；
- 侧栏工具行：「＋ 项目」「AI 归类」「记忆 N」「⚙」；
- 点击会话继续打开原版 DeepSeek 对话；
- 使用 `chrome.storage.local` 保存任务和会话归属（接入记忆文件夹后文件夹为唯一真相源）；
- 可选开启 AI 自动归类：新会话首轮完成后，调用 DeepSeek 在现有项目中做一次受约束选择；
- 右侧栏展示整理状态、任务进度、约束/决定/阻塞统计、任务会话和下一步；
- 可直接编辑概况和下一步，添加、修改、固定、推进或退役结构化记忆条目；
- 可一键复制任务上下文，或打开该任务最近的 DeepSeek 会话；
- 为每个任务维护结构化任务记忆：概况、下一步、目标、约束、决定、里程碑和阻塞；
- 维护跨任务用户事实：非敏感资料、稳定偏好、工作方式和术语，可人工编辑或禁用；
- 从任务详情栏启动独立的 DeepSeek 整理请求，读取任务内会话原文并生成记忆更新；
- 对整理结果执行 JSON、作业版本、会话归属、枚举和来源证据校验，失败时保留旧记忆；
- 人工固定的任务条目不会被模型覆盖，禁用的用户事实不会因重整旧历史而自动复活。
- 可选开启「自动注入」：任务会话的每条消息发送前，自动把该任务记忆以 `<task_memory>` 块注入请求；
- 可选开启「每 5 轮自动整理」：任务内每累计 5 轮完成的对话，自动复用整理管线更新任务记忆；
- AI 归类结果只有在项目 ID 属于当前候选集且置信度不低于 `0.6` 时才会执行；否则会话保持未分类。
- 可选接入本地记忆文件夹（File System Access）：任务记忆、用户事实与会话原文以 JSON 文件落盘，文件夹为唯一真相源，支持手改后重载与授权失效降级。
- 侧栏 ⚙ 设置页：AI 归类、自动注入/自动整理/原文存档开关、自动整理轮数阈值（3–30，默认 5）、记忆文件夹状态与管理入口、从文件夹重新载入。

删除项目只会解除本插件中的归类；项目中的 DeepSeek 会话不会被删除，而是回到「未分类会话」。

## 目录结构

```
core/              扩展根目录（chrome://extensions 加载这里）
  logic/           纯逻辑核心（无 DOM/Chrome API）：memory / history / request-body / fs
  background/      service worker：记忆管线编排与全部文件 IO
  content/         内容脚本与样式：项目树侧栏、任务详情、设置页
  page/            MAIN world 网络钩子（请求体改写）
  popup/           工具栏弹窗：记忆文件夹授权与重载
tests/             离线自检与真实环境端到端脚本
docs/              设计文档与 DOM 侦查输出
.live-profile/ .live-fs/   真实测试的运行时产物（gitignore）
```

## AI 归类、自动注入与自动整理

三个云端开关默认关闭，首次开启会明确提示发送范围。AI 归类可从侧栏工具行或 ⚙ 设置切换；自动注入和自动整理也在项目详情底部。自动整理的轮数阈值默认 5，可改为 3–30。

**AI 自动归类**：新会话首轮回复完成后，插件读取会话标题与最多 12000 字符对话原文，在非激活 DeepSeek 标签页发起一次分类请求。模型只允许返回一种模拟 function call：

```json
{"tool":"move_conversation_to_project","arguments":{"job_id":"…","conversation_id":"…","project_id":"现有项目 ID 或空字符串","confidence":0.8,"reason":"…"}}
```

后台会校验工具名、作业 ID、会话 ID、候选项目白名单和置信度。只有校验通过且 `confidence >= 0.6` 时才更改归属；返回空项目、低置信度、超时或校验失败都保持「未分类」。会话内容一律按不可信数据处理，不能改变允许的工具或候选项目。该请求可能在 DeepSeek 历史中留下维护会话。

**自动注入**：开启后，当前会话所属任务（未绑定则为选中任务）的记忆会渲染成 `<task_memory>` 块，由 MAIN world 网络钩子在 `/api/v0/chat/completion` 与 `/edit_message` 出站前前缀到最后一条用户消息上。注入只发生在未 armed 的普通聊天请求上；整理维护请求（带随机标记）永远不会被注入。注入失败或请求体不可解析时原样放行，不影响原生聊天。注意：DeepSeek 服务端会保存注入后的文本，因此刷新后历史消息里会完整显示该块——这是有意为之，让用户始终能看到实际注入了什么；同一对话里以最后一个记忆块为准。

**每 5 轮自动整理**：内容脚本在每次回复完成（停止生成且文本稳定 3 秒）后向后台报告一轮完成，按消息指纹去重防止刷新重复计数。只有已归属项目的会话会计入该项目；每累计 5 轮自动触发一次与手动「↻ DeepSeek 更新」完全相同的整理管线（读取历史接口 → 隐藏标签页整理 → 校验 → 提交）。某轮整理失败时保留计数，可手动重试。

## 记忆更新如何工作

在任务详情栏点「↻ DeepSeek 更新」。插件会在任务会话页面通过 `/api/v0/chat/history_messages` 读取完整消息历史；只有历史接口不可用时才回退到页面 DOM。随后它会在一个非激活标签页中发起 DeepSeek 整理请求。页面输入框只放入带随机 ID 的一次性标记；MAIN world 网络钩子在 `/api/v0/chat/completion` 或 `/api/v0/chat/edit_message` 出站前，直接把请求体中最后一条用户消息替换为完整整理上下文。DeepSeek 只返回受约束的 JSON；插件本地校验通过后才提交新版本。

请求体改写采用一次性指令并校验随机标记。未携带匹配标记的正常用户请求不会被修改；改写失败时也不会把完整上下文回填到页面输入框。`fetch` 和 `XMLHttpRequest` 两条请求链均受支持，原请求的 headers、credentials、signal 等参数会被保留。

记忆保存在 `chrome.storage.local`，但整理输入会发送到 DeepSeek，并可能在 DeepSeek 历史中留下一个维护会话。首次使用时插件会明确提示这一点。浏览器标签页会在整理完成后关闭，远端会话不会被插件偷偷删除。

## 本地文件夹存储

点击浏览器工具栏的扩展图标打开管理弹窗，选择一个文件夹后，该文件夹成为任务记忆与用户事实的唯一真相源；`chrome.storage.local` 退化为运行时副本（作业队列、轮次指纹、开关等运行时状态仍只在浏览器内）：

```
<选择的文件夹>/
  meta.json                      结构版本
  facts.json                     { updatedAt, facts: [...] }
  tasks/<taskId>.json            单个任务的完整记忆（概况/条目/证据/历史快照）
  conversations/<会话id>.json     整理时采集的会话原文存档（只写不读）
```

- **合并规则**：插件与文件夹按记录 `updatedAt` 新者胜，平局文件胜。手动编辑 `tasks/<id>.json` 后把该文件的 `updatedAt` 改成较新的时间，插件落盘时不会覆盖它；点弹窗里的「从文件夹重新载入」可让文件夹整体生效（浏览器副本中没有对应文件的任务会被移除）。
- **facts.json 的 `updatedAt` 是信封时间戳**：手改后同样需要把它改成较新时间，否则会在下次合并中被浏览器副本赢回。
- **降级**：授权失效或文件夹被删时，扩展图标显示 `!`、侧栏显示提示条，所有更改仍写入浏览器副本（数据不丢）；点弹窗重新授权或重选文件夹后按时间戳自动补齐双向差异。
- 首次授权时如果文件夹为空而浏览器里已有记忆，会自动导出（迁移）。

当前版本为避免隐性信息丢失，不会静默截断超长整理输入；任务原文累计超过 50000 字符或完整整理提示超过 60000 字符时，会保留旧记忆并提示失败。历史接口不可用且只能回退到 DOM 时，未呈现的懒加载消息仍会被标记为不完整采集。

## 本地加载

1. 打开 `chrome://extensions/`。
2. 开启“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择本仓库的 `core` 文件夹。
5. 刷新 `https://chat.deepseek.com/`。


用本机 Chrome 携带本目录扩展直连真实 `chat.deepseek.com`：首次运行会在弹出的窗口中要求登录一次（登录态保存在 `.live-profile/`，之后复用），并在中途要求在弹出的扩展弹窗里选择 `.live-fs/` 作为记忆文件夹（共两次）。脚本会种子一个测试项目，发送一条真实消息，模拟手动移入项目，再验证自动注入、回复完成计数、历史接口（含 `INVALID_TOKEN` 重试路径）、完整的「DeepSeek 更新记忆」管线、文件夹迁移导出、会话原文存档、手改文件重载以及降级恢复。

## 页面改动边界

插件不移动或重建 DeepSeek 的 React 会话节点，但会隐藏原生日期分组的视觉输出，在同一滚动容器中渲染轻量项目树。项目树点击会话时复用隐藏的原生链接，点 `•••` 时复用原生菜单；插件只在菜单尾部追加项目操作。工具区和树节点均带 `dtw-owned` 标记，项目详情、记忆弹窗与 toast 挂在 `#dtw-root`；聊天主内容区结构不变。因为侧栏适配依赖 DeepSeek DOM，站点大改版时需重新校验。
